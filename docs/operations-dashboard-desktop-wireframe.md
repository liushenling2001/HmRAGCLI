# 运维面板桌面端线框说明

## 1. 画布建议

建议桌面端基准画布：

```text
1440 x 1024
```

外边距建议：

```text
左右 32
顶部 24
底部 24
```

内容网格建议：

```text
12 columns
gutter 16
```

---

## 2. 页面整体结构

页面从上到下建议分为 6 层：

1. 顶部导航栏
2. 系统状态条
3. KPI 卡片区
4. 数据源卡片区
5. 任务与失败双栏区
6. 底部留白或抽屉层

---

## 3. 顶部导航栏

高度建议：

```text
64
```

左侧：

1. Logo / 产品名
2. 页面标题 `Operations Dashboard`

右侧：

1. 最后刷新时间
2. `刷新状态`
3. `开始扫描`
4. `开始入库`

建议布局：

```text
左对齐标题，右对齐动作按钮
```

---

## 4. 系统状态条

高度建议：

```text
80
```

放置 5 个状态块：

1. Database
2. AI
3. Embedding
4. LibreOffice
5. Parser

每个状态块包含：

1. 组件名
2. 状态点
3. 一行简短说明

建议每块宽度：

```text
220 - 240
```

状态颜色：

1. `OK` 绿色
2. `Warning` 橙色
3. `Error` 红色

---

## 5. KPI 卡片区

建议布局：

```text
两行，每行 5 卡
```

单卡建议尺寸：

```text
约 240 x 104
```

卡片内容结构：

1. 指标名称
2. 主数值
3. 辅助说明

### 第一行卡片

1. 数据源总数
2. 文件总数
3. 成功文件
4. 失败文件
5. 待处理文件

### 第二行卡片

1. 文档总数
2. 业务文档数
3. 开发文档数
4. Chunk 总数
5. Knowledge Unit 总数

---

## 6. 数据源卡片区

建议标题栏：

1. `Data Sources`
2. 一个数据源筛选输入框
3. `查看全部` 按钮

卡片建议为：

```text
2 列网格
```

单卡建议尺寸：

```text
约 680 x 180
```

卡片内部布局：

### 上半区

1. 数据源名称
2. 数据源类型标签
3. 根目录路径

### 中间状态区

1. 总文件数
2. 待处理
3. 处理中
4. 成功
5. 失败
6. 精确重复

### 底部操作区

1. 最近扫描时间
2. 最近入库时间
3. `查看文件`
4. `扫描`
5. `入库`

---

## 7. 最近任务与失败文件区

建议为两列布局：

```text
左 7 列，右 5 列
```

### 左侧：最近任务

模块标题：

1. `Recent Jobs`
2. 筛选栏

筛选栏建议：

1. Job Kind 下拉
2. Status 下拉
3. Data Source 下拉

表头列建议：

1. 类型
2. 数据源
3. 状态
4. 总文件
5. 成功/失败
6. 时间

表格建议高度：

```text
420 - 480
```

### 右侧：失败文件

模块标题：

1. `Recent Failures`
2. 筛选栏

筛选栏建议：

1. 文件类型
2. parse_status
3. 数据源

每一行建议显示：

1. 文件名
2. 文件类型标签
3. 当前阶段
4. parse_status
5. 错误摘要
6. 更新时间

行内操作：

1. `重入库`
2. `重抽取`
3. `重建向量`

---

## 8. 抽屉与详情交互

建议不要在首页放过多细节，使用右侧抽屉展示。

适合用抽屉的对象：

1. Job 详情
2. 失败文件详情
3. 数据源详情摘要

抽屉宽度建议：

```text
420 - 480
```

抽屉内容建议：

1. 基本信息
2. 当前状态
3. 关键时间
4. 错误信息
5. 快捷操作

---

## 9. 页面交互建议

### 9.1 刷新策略

建议：

1. 手动刷新为主
2. 可选 30 秒自动刷新

### 9.2 任务列表交互

建议：

1. 点击行打开右侧抽屉
2. 状态支持快速过滤

### 9.3 失败文件交互

建议：

1. 失败类型红色高亮
2. `conversion_failed` 单独加图标
3. 支持一键重试

---

## 10. 桌面端首屏优先级

首页首屏必须先看到：

1. 系统是否健康
2. 有没有失败文件
3. 哪个数据源积压最多
4. 最近任务是否异常

所以优先级顺序建议：

1. 顶部状态
2. KPI
3. 数据源
4. 最近任务
5. 失败文件

---

## 11. 与 API 的映射

### 顶部状态条

接口：

1. `GET /api/v1/system/health`

### KPI + 数据源卡片 + 首页任务 + 首页失败

接口：

1. `GET /api/v1/operations/dashboard`

### 全量任务页

接口：

1. `GET /api/v1/operations/jobs`

### 全量失败页

接口：

1. `GET /api/v1/operations/failures`

### 单数据源详情

接口：

1. `GET /api/v1/data-sources/{id}`
2. `GET /api/v1/data-sources/{id}/files`
